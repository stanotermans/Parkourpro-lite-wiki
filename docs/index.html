02Installation

One jar, no hard dependencies. Everything else is optional and detected automatically.

  1. Drop the jar in plugins/

    Use ParkourPro-1.0.9.jar or ParkourProLite-1.0.9.jar. Never run both editions at the same time.

  2. Restart the server

    The plugin writes config.yml, parkours.yml, records.yml and a languages/ folder with all 23 translations.

  3. Pick a language and storage

    Set language in config.yml (for example nl_NL). Enable mysql if you run a network, otherwise records stay in records.yml.

  4. Optional add-ons

    LuckPerms (rank prefixes on holograms), PlaceholderAPI (placeholders), WorldGuard (region restriction), ItemsAdder (custom icons in the timer), and for Pro a Discord bot token.

  5. Apply changes with /parkour reload

    Reloads config, parkours, holograms and languages without a restart. New message keys are added to existing language files automatically.

Upgrading? Replace the old jar with the new one and restart. All existing configurations and records stay compatible. Switching between Pro and Lite copies records.yml from the other edition's folder on first start.

03Your first parkour

A course is three kinds of pressure plates. Look at a plate while running each command.

🟨

Gold plate = start

Light weighted pressure plate. Stepping on it starts the run and the timer.

🟨

Gold plate = end

A second gold plate finishes the run and saves the time.

⬜

Iron plates = checkpoints

Heavy weighted pressure plates, added in order. Players must activate them in sequence and teleport back to the last one they reached.

  1. Set the start

    Look at a gold plate and run:

    /parkour setstart sky
  2. Set the end

    Look at the finish gold plate:

    /parkour setend sky
  3. Add checkpoints

    Look at each iron plate in course order. Repeat for every checkpoint. Checkpoints are optional.

    /parkour addcheckpoint sky
  4. Set the reset location

    Stand where players should land after /parkour reset or a fall without checkpoints:

    /parkour setreset sky
  5. Add a leaderboard

    Look at a block where the top list should float:

    /parkour addleaderboard sky
/parkour setleaderboardsize sky 10
  6. Protect the course from falls

    Teleport players back when they drop below Y 60:

    /parkour setfallback y sky 60
/parkour togglefallback sky
Tip. Prefer a guided flow? The creation wizard walks you through start, end and checkpoints with validation at every step.

06Records & leaderboards

A record is one best time per player per parkour. Only faster runs replace it, unless an admin overrides it with settime.

Where records are stored

  • Local: plugins/ParkourPro/records.yml (or the Lite folder). Always written, even with MySQL on, so you keep a local copy.
  • MySQL: table <prefix>records with one row per player and parkour. Shared across a network, all queries run off the main thread.
  • Leaderboards read from MySQL first and fall back to the local file.

Managing records

/parkour deletetime sky Notch           # wipe Notch's time on "sky"
/parkour settime sky Notch 01:23.456  # set Notch's time to 1 min 23.456 s

Player lookup works for offline players: the plugin checks online players, then stored records on that parkour, then records on any parkour, then the server's player data. After both commands the leaderboard hologram is redrawn immediately and PlaceholderAPI values refresh within five seconds.

07Holograms

Every parkour can show a start, end, per-checkpoint and leaderboard hologram. Default text comes from config.yml; per-parkour text from sethologram.

Renderers

  • Legacy (1.8 – 1.19): invisible armor stands, one per line. Rock solid on every server.
  • Modern (1.19.4+ Paper): text displays with background, opacity, scale and billboard settings via sethologramdisplay.
  • HologramLib renderer (Pro, 1.20+): enable holograms.modern-renderer.enabled for packet-based holograms and player heads on leaderboard rows (heads render on 1.21.10+).

Offsets and visibility

start-offset, end-offset, checkpoint-offset and leaderboard-offset raise the hologram above its plate. line-spacing sets the gap between lines. visibility-range hides holograms beyond that many blocks (0 = always visible). The leaderboard refreshes every update-interval seconds and immediately after a record change.

11Gameplay & anti-cheat

Hotbar items

When a run starts the player's inventory is stored and replaced by three items: a plate to teleport to the last checkpoint, a door to reset, and a bed to cancel (double-click). The inventory is restored on finish, cancel or leave. Dropping or moving the items is blocked.

Checkpoints in order 1.0.8

Checkpoints must be activated in sequence. Stepping on checkpoint 3 while checkpoint 2 was never reached does nothing except a "you skipped a checkpoint" message, so finishing always means every checkpoint was really touched. Pro can lower the number required with setrequiredcheckpoints, still counted in order. Legacy behaviour is available with checkpoints.sequential: false.

Checkpoint splits 1.0.9

Every checkpoint shows the elapsed time and the difference with your own record, green when you are ahead and red when behind. Splits are stored with the record and listed by /parkour pb.

Statistics 1.0.9

Attempts, completions, play time and race wins per player and parkour, in stats.yml and MySQL. Shown by pb, the menu, placeholders and the web API.

Cooldown, daily limit and leave radius 1.0.9

Per parkour: a cooldown between finishes, a maximum number of starts per day, and a radius around the plates outside of which the run is cancelled.

Timer

Shows elapsed time and checkpoints reached. /parkour reset restarts it; with restart-on-same-start stepping on the start plate again does too.

Fly and teleport detection

Flying players return to their checkpoint. With detect-teleport on, teleports and /tp are blocked during a run. Plugin teleports (checkpoint, reset) are always allowed.

Fallback

A Y-level fallback per parkour or globally. Pro adds the fall-blocks rule: drop more than N blocks from your highest point since the last checkpoint and you are sent back, which works on courses at any height.

Death

Deaths can keep players in the run and respawn them at their checkpoint or the start, per parkour or globally.

Locks and progression

Require a permission or a previously finished parkour before a player may start. Toggle all locks at once with togglelocks.

Rewards

End commands run on every finish, first-completion rewards run once per player, and new records can be broadcast to the server or world.

12Pro features Pro

Proximity finish 1.0.8

Enable togglefinishproximity and the run ends as soon as the player is within the radius of the end plate, even when the plate is never pressed. Ideal for courses that end with a jump onto the finish, or for players who sneak. Required checkpoints, records, rewards and redirects behave exactly as with the plate.

Ghost replay 1.0.9

Every run is sampled about twenty times per second. When a run becomes the fastest time on a parkour it is saved to ghosts/<parkour>.yml. /parkour ghost replays it in real time as an armor stand with the player's head, optionally looping or starting automatically with every run.

Race mode 1.0.9

A host creates a race, players join, a countdown with titles freezes everyone on the start plate and all runs start on GO. Positions are announced, the winner gets the configured commands and a race win in the statistics.

Daily, weekly and monthly leaderboards 1.0.9

Every finish updates the best time for the current day, ISO week and month. Show them in chat, as extra holograms per parkour, or through the API. Old periods are pruned automatically.

Seasons 1.0.9

Closing a season pays the rewards in seasons.rewards to the top players of every parkour, archives all records to records_archive.yml or the archive table, and resets the leaderboards. The change is broadcast and posted to the Discord webhook.

Rewards by time and rank 1.0.9

Commands for finishing under a time (every run), for landing on a leaderboard position and for any new personal best, with %player%, %parkour%, %time% and %pos%.

Speed check 1.0.9

Resets players that move faster than max-horizontal-speed blocks per movement packet for speed-strikes packets in a row. Speed potions raise the limit. Off by default; tune it per server.

Network sync 1.0.9

With a shared MySQL database, mysql.sync-interval polls for records set on other servers and refreshes the affected leaderboard holograms right away.

Web API 1.0.9

Read-only JSON on its own port: parkours, leaderboards per period, a player's records and statistics, and the season state. Protect it with a bearer token.

Time limits and penalties

settimelimit puts a countdown in the timer. When it expires the player is sent to the leave position and penalty commands run. Offline-penalty commands run when a player disconnects mid-run, so leaving to dodge a penalty does not work.

Special pressure plates

Effect plates give a jump boost or levitation. Build plates place temporary blocks at configurable offsets and remove them again, for bridges that appear as you run.

Medals

Run togglemedals, complete the course yourself as the calibration run, confirm, and gold, silver and bronze thresholds are derived from it. Reward commands per medal fire when a player earns or improves a medal.

Hide players and dynamic holograms

Hide other runners' bodies, tab entries or chat inside the same parkour. Dynamic hologram visibility shows each player only the hologram for their next target.

Checkpoint management

Delete or move checkpoints without rebuilding the course, and require only a subset of checkpoints to finish.

Testing mode

Switch a parkour to testing mode while you tweak it and no first-completion rewards are paid out.

WorldGuard and ItemsAdder

Restrict all plates to WorldGuard regions. With ItemsAdder the timer shows custom icons for time and checkpoints.

13Discord bot Pro

A built-in bot that answers /scoreboard parkour:<name> with a rich embed of the top times.

  1. Create a bot

    In the Discord Developer Portal create an application, add a bot and copy its token. Invite it with the applications.commands scope.

  2. Configure

    Set discord.enabled: true, paste the token and optionally a guild-id for instant command registration.

  3. Style the embed

    title, color, entry-format (%pos%, %player%, %time%, %rank%), footer, empty-message, column labels and leaderboard-size. With LuckPerms and show-prefix the rank prefix is included.

  4. Reload

    /parkour reload re-registers the slash command.

Player heads can be shown inline as guild emojis (inline-head-emojis); head URLs are cached for avatar-cache-minutes.

13bWeb API Pro 1.0.9

A read-only JSON API for websites, Discord bots or dashboards. Enable it with web-api.enabled: true.

GET /api/parkours
GET /api/leaderboard/<parkour>?limit=10&period=alltime|daily|weekly|monthly
GET /api/player/<name>
GET /api/stats/<parkour>

With web-api.token set, send Authorization: Bearer <token> or ?token=. Responses carry Access-Control-Allow-Origin: * so a browser page can call them directly. Leaderboard entries include the checkpoint splits of each record.

15FAQ & troubleshooting

Not answered here? Ask on the Discord server.

The start plate does nothing

The parkour needs both a start and an end (setstart and setend). Check that the plate is a gold plate and, in Pro, that it lies inside the WorldGuard region when that restriction is enabled. Locked parkours also require the permission or prior completion.

Players get "you must complete all checkpoints"

All checkpoints are required and must be activated in order. A player who skipped one sees "you skipped a checkpoint" on later plates and has to go back. Use setrequiredcheckpoints <parkour> <number> to require fewer. Make sure checkpoints were added in course order.

Command blocks teleport players and they get reset

Set anti-cheat.detect-teleport: false. The threshold only applies while that option is on.

Holograms are invisible or duplicated

Run /parkour reload, which removes and recreates every hologram. Check holograms.visibility-range. On modern Paper builds where the modern renderer causes issues, keep modern-renderer.enabled: false.

A cheater is on top of the leaderboard

/parkour deletetime <parkour> <player>. The hologram refreshes immediately. If a player's record is wrong, correct it with settime.

Records disappeared after switching between Pro and Lite

Both editions keep their own folder. On first start the plugin copies records.yml from the other edition's folder when its own file has no records. With MySQL both editions share the same table.

The time limit does not start

A time limit needs a leave position: /parkour setleaveposition <parkour> first.

Which version of Java do I need?

Java 8 or newer. The jar is compiled to Java 8 bytecode and has been run on Java 8 through 25.
